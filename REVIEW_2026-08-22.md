## CRITICAL (3) — деньги / безопасность / данные

### C1. Multi-proxy refund ревокает только ОДИН access
app/api/admin/domain.py:2439-2443 — refund ревокает только один active access (`session.scalar(...)`) и ставит order.status="refunded" при ЛЮБОМ размере возврата. Multi-proxy заказ (quantity до 50, orders.py:131): возвращены все деньги, 49 доступов продолжают работать. При частичном рефанде ($1 из $85) доступ ревокается целиком.
Фикс: цикл по всем Access заказа со статусами _ACTIVE_ACCESS; статус "refunded" только при already_refunded + amount >= order.amount_usd, при частичном — без revoke.

### C2. Provisioner не имеет prod-гварда
app/services/provisioning/registry.py:13-18 — get_provisioner() не имеет prod-гварда, в отличие от payments/registry.py:18-21. FEATURE_REAL_PROVISIONING=false на проде → MockProvisioner молча "выдаёт" фейковые прокси за реальные деньги, expiry/revoke — no-op.
Фикс: `if settings.is_prod and not settings.feature_real_provisioning: raise RuntimeError(...)` плюс проверка iproxy_api_key.

### C3. watch_payout_transfers читает config без session (повтор прод-бага "рельсы без сессии")
app/workers/tasks/jobs.py:212-241 — get_onchain_config() читается БЕЗ refresh_rails(s), в отличие от watch_onchain_deposits (jobs.py:180-181). При payment_provider!="onchain" (deposits-тик no-op) payout-конфиг НИКОГДА не подтянется из консоли — auto-confirm выплат молча не работает.
Фикс: `async with SessionFactory() as s: await refresh_rails(s)` в начале job'а.
